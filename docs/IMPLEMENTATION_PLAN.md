# Implementation Plan

## 1. Existing code and assets — DONE
The v1 static design system and infrastructure were retained where they were stable. The website layer was migrated from hand-built HTML/Python templating to Astro without adding a client framework.

## 2. Architecture and tokens — DONE
Astro 7 SSG + TypeScript. Typed PL/EN content, file-based routes, shared components and CSS design tokens. Runtime output remains static HTML/CSS/assets.

## 3. Experience architecture — DONE
Five routes per locale: home, about, OAF, work and writing. Polish is canonical without a prefix; English mirrors all routes under `/en`.

## 4. Responsive layout — DONE baseline
Fluid typography/spacing with structural breakpoints at 960px and 620px, tested design target down to 320 CSS px.

## 5. Content and localization — DONE baseline
Full English route parity is included. OAF remains an original working model without inventing an acronym expansion. Case studies remain intentionally unpublished pending anonymization/approval.

## 6. Motion — SIMPLIFIED
No required client JavaScript. The architecture intentionally removes decorative reveal scripts; hover transitions are subtle and disabled by `prefers-reduced-motion`.

## 7. Accessibility / SEO / performance — DONE engineering baseline
WCAG 2.2 AA target, semantic landmarks, skip links, keyboard-native mobile navigation, visible focus, language-of-page/parts, 320px reflow, target sizing, high-contrast preference and axe/Playwright CI. Canonical/hreflang, sitemap, robots and JSON-LD are generated by Astro.

## 8. Testing — DONE by configuration
`astro check`, static localized-route validation, Playwright + axe on desktop/mobile Chromium, Docker build and Trivy HIGH/CRITICAL gate.

## 9. Deployment — LOCAL ONLY
macOS, Docker Desktop and local Kubernetes remain active. Azure/public artifacts stay future-ready but disabled.
