# Visual Storytelling — Phase 2

## Creative Direction

Move the site from **text explaining systems** to **systems made visible**. The visual language stays editorial and executive: warm paper, dark decision fields, architecture marks, explicit trade-offs and restrained motion. No SaaS dashboards, decorative 3D, stock-consulting imagery or invented metrics.

## Experience Architecture

Phase 2 does not add more sections to Home. It deepens the pages where the reader already expects evidence and application:

- **Perspective** — benchmark evidence becomes a visual signal field with source links and progressive disclosure for interpretation.
- **Advisory** — the repeated output list is replaced by a concrete decision canvas; the top of the page shows a before/after decision architecture instead of another generic system diagram.
- **Home** — remains the executive summary and keeps the existing decision-system map/output blueprint rather than accumulating more visual modules.

## Design System

New visual primitives:

1. **Benchmark signal field** — independent research signals shown as separate rulers, not falsely normalized into one comparable chart.
2. **Decision architecture delta** — fragmented local decisions → explicit hand-offs → connected decision backbone with feedback.
3. **Portfolio trade-off matrix** — an illustrative decision canvas showing how strategic relevance, dependencies and capacity can be made visible enough to support stop / merge / sequence / continue choices.

All visuals are semantic HTML + CSS. No client framework and no essential JavaScript. Mobile layouts rebuild the diagrams linearly rather than scaling desktop geometry down.

## Content Rules

- Visualize only claims already supported by source material or clearly label an artifact as illustrative.
- Never imply cross-study comparability where methodologies differ.
- Never fabricate client names, logos, KPI values or pseudo-precision.
- Prefer progressive disclosure for explanatory text that is not needed for first-pass executive scanning.
- Use diagrams to make a decision or trade-off clearer, not as decoration.

## Phase 3 backlog

Only after Phase 2 is visually accepted:

- 2–3 publishable anonymized case blueprints with real decision context;
- real speaking / workshop / whiteboard photography when suitable assets exist;
- one original Perspective data visualization backed by a larger benchmark corpus;
- capability / architecture map example using truthful publishable material;
- optional case-specific before/after operating model visual.

Do not add these merely to make the site busier. Each item must improve comprehension, credibility or conversion.
